# Academic Planner: MVP Specification (agent-ready, v2)

**Goal:** A local-first, open-source desktop app for university courses, weekly timetables, assessments, and manually logged attendance. Native desktop UI (no WebView), no account, no server.

**How to use this spec with a coding agent:** Build milestones **M0 → M6 in order**, one milestone per agent session. A milestone is done only when its **Done-when** commands pass. Rule IDs (`R*`) and test IDs (`T*`) are referenced from code comments and test names so the agent and the reviewer can trace coverage. **The MVP is usable after M4** (`cargo run -p app`). M5 and M6 are polish and distribution.

---

## 1. Fixed decisions (do not re-decide)

| Area | Decision |
|---|---|
| Language | Stable Rust, edition 2021, `Cargo.lock` committed |
| UI | Slint (`.slint` files compiled in `build.rs`) |
| DB | SQLite via `rusqlite` with `bundled`; `PRAGMA foreign_keys=ON`, `journal_mode=WAL` |
| Migrations | Hand-rolled: embedded SQL files, version tracked with `PRAGMA user_version` |
| Dates | `chrono` **naive local** types only (`NaiveDate`, `NaiveTime`, `NaiveDateTime`). No time zones. Stored as TEXT: `YYYY-MM-DD`, `HH:MM`, `YYYY-MM-DDTHH:MM` |
| Clock | Core never reads the system clock. Every time-dependent function takes `today`/`now` as a parameter. Enforced by `clippy.toml` `disallowed-methods` (`chrono::Local::now`, `chrono::Utc::now`, `std::time::SystemTime::now`) in the core crate |
| Errors | `thiserror` in core, `anyhow` in app |
| Serialization | `serde`, `serde_json`, `csv` |
| Paths | `directories::ProjectDirs` data dir; env var `ACADEMIC_PLANNER_DB` overrides the DB path (dev/tests) |
| File dialogs | `rfd` |
| Notifications (M5) | `notify-rust` |
| Saving | Every mutation commits immediately. No save button |
| Weekday | ISO numbering: 1 = Monday … 7 = Sunday |
| License | Decide in **M0**, not at release, because the Slint license option constrains the repo license. Verify Slint's current license terms and note any attribution requirement in `NOTICE`/README |

## 3. Data model (exact schema, migration 001)

```sql
CREATE TABLE term (
  id          INTEGER PRIMARY KEY,
  name        TEXT NOT NULL,
  start_date  TEXT NOT NULL,
  end_date    TEXT NOT NULL,
  is_active   INTEGER NOT NULL DEFAULT 0,
  CHECK (end_date >= start_date)
);
CREATE UNIQUE INDEX one_active_term ON term(is_active) WHERE is_active = 1;

CREATE TABLE holiday (
  term_id  INTEGER NOT NULL REFERENCES term(id) ON DELETE CASCADE,
  date     TEXT NOT NULL,
  label    TEXT,
  PRIMARY KEY (term_id, date)
);

CREATE TABLE course (
  id                  INTEGER PRIMARY KEY,
  term_id             INTEGER NOT NULL REFERENCES term(id),
  code                TEXT NOT NULL,
  name                TEXT NOT NULL,
  instructor          TEXT,
  room                TEXT,
  notes               TEXT,
  min_attendance_pct  INTEGER CHECK (min_attendance_pct BETWEEN 0 AND 100),
  archived            INTEGER NOT NULL DEFAULT 0,
  UNIQUE (term_id, code)
);

CREATE TABLE slot (                         -- recurring timetable rule
  id          INTEGER PRIMARY KEY,
  course_id   INTEGER NOT NULL REFERENCES course(id),
  weekday     INTEGER NOT NULL CHECK (weekday BETWEEN 1 AND 7),
  start_time  TEXT NOT NULL,
  end_time    TEXT NOT NULL,
  room        TEXT,                         -- NULL = use course.room
  valid_from  TEXT NOT NULL,                -- inclusive
  valid_to    TEXT,                         -- inclusive; NULL = until term end
  CHECK (end_time > start_time)
);

CREATE TABLE session (                      -- one dated class occurrence
  id                   INTEGER PRIMARY KEY,
  course_id            INTEGER NOT NULL REFERENCES course(id),
  slot_id              INTEGER REFERENCES slot(id),          -- NULL for makeup
  kind                 TEXT NOT NULL CHECK (kind IN ('regular','makeup')),
  date                 TEXT NOT NULL,
  start_time           TEXT NOT NULL,
  end_time             TEXT NOT NULL,
  room                 TEXT,
  status               TEXT NOT NULL DEFAULT 'pending'
                       CHECK (status IN ('pending','attended','absent','cancelled')),
  replaces_session_id  INTEGER REFERENCES session(id),       -- set on a makeup that reschedules an original
  note                 TEXT,
  UNIQUE (slot_id, date),
  CHECK (end_time > start_time),
  CHECK ((kind = 'regular') = (slot_id IS NOT NULL))
);

CREATE TABLE assessment (
  id                      INTEGER PRIMARY KEY,
  course_id               INTEGER NOT NULL REFERENCES course(id),
  kind                    TEXT NOT NULL CHECK (kind IN ('quiz','exam','assignment','other')),
  title                   TEXT NOT NULL,
  due_at                  TEXT NOT NULL,
  notes                   TEXT,
  completed               INTEGER NOT NULL DEFAULT 0,
  remind_minutes_before   INTEGER CHECK (remind_minutes_before >= 0)  -- NULL = no reminder
);

CREATE TABLE setting (key TEXT PRIMARY KEY, value TEXT NOT NULL);
-- defaults: class_reminder_minutes=15, upcoming_window_days=7, notifications_enabled=1

CREATE TABLE reminder_log (                 -- M5: prevents duplicate notifications
  kind     TEXT NOT NULL CHECK (kind IN ('session','assessment')),
  ref_id   INTEGER NOT NULL,
  fire_at  TEXT NOT NULL,
  PRIMARY KEY (kind, ref_id, fire_at)
);
```

There is **no "rescheduled" status**. A rescheduled occurrence is `status='cancelled'` and is referenced by a makeup session's `replaces_session_id`. The UI derives the label "Rescheduled → {date}".

## 4. Business rules

**Terms and courses**
- **R1** Exactly zero or one active term. Courses, sessions, dashboard, and summaries operate on the active term.
- **R2** Validation errors (returned as `Error::Validation`, never panics): term end < start; slot end ≤ start; `min_attendance_pct` outside 0–100; empty course code/name/assessment title; duplicate course code within a term.
- **R3** Archiving a course hides it from the dashboard, timetable, and default lists. Its sessions and assessments are kept, and it generates no new sessions. Unarchiving resumes generation on the next sync.

**Session generation**: `sync_sessions(today)`, idempotent
- **R4** For each slot of each non-archived course in the active term, the generation range is `[max(term.start, slot.valid_from), min(term.end, slot.valid_to ?? term.end)]`, both ends inclusive. Every date in that range with `weekday == slot.weekday` that is **not a holiday** gets exactly one `regular` session (`UNIQUE(slot_id,date)`), copying start/end/room from the slot at creation time.
- **R5** Sync deletes a session only if **all** of these hold: `kind='regular'`, `status='pending'`, `date >= today`, and it is no longer produced by R4. Past sessions and any non-pending session are never deleted by sync.
- **R6** Sync runs on app start, after any term/holiday/course/slot change, and when the date rolls over (checked by the app's 60-second timer).
- **R7** Editing a slot = `change_slot(slot_id, new_values, effective_from)`: set old slot `valid_to = effective_from - 1 day`, insert a new slot with `valid_from = effective_from`, then sync. Past sessions keep their stored date/time/room (**sessions are snapshots**). UI default for `effective_from` is today.

**Exceptions**
- **R8** Cancel an occurrence: set that session's status to `cancelled`. The slot is unchanged, and sync never recreates or resets it.
- **R9** Reschedule (one transaction): create a `makeup` session with `replaces_session_id = original.id`, and set the original to `cancelled`. Rescheduling a session that is already attended or absent is an error.
- **R10** One-off makeup class: a `makeup` session with `replaces_session_id = NULL`. It counts like any other session.

**Attendance**
- **R11** Statuses: `pending` (default), `attended`, `absent`, `cancelled`. Attendance is never inferred automatically.
- **R12** `attended`/`absent` can be set only when `now >= session start`. `cancelled` and reset-to-`pending` are allowed at any time.
- **R13** `pct = attended / (attended + absent) × 100`, rounded to 1 decimal. If the denominator is 0, return `None`; the UI shows "—".
- **R14** `below_target = target.is_some() && pct.is_some() && pct < target`.
- **R15** The summary per course returns counts of attended, absent, cancelled, and pending (past + future), plus `pct` and `below_target`.

**Dashboard**: `dashboard(now)`
- **R16** Today's classes: all sessions with `date == now.date()` for non-archived courses, sorted by start, with status.
- **R17** Next class: the earliest `pending` session with `start > now` (non-archived).
- **R18** Upcoming assessments: incomplete, `now <= due_at <= now + upcoming_window_days`, sorted by due date.
- **R19** Overdue: incomplete with `due_at < now`.
- **R20** Awaiting attendance: `pending` sessions with `end <= now` (non-archived), oldest first. Sessions in progress are not included.

**Backup and export**
- **R21** `export_json(now)` → `{"format":"academic-planner-backup","schema_version":N,"exported_at":"…","terms":[],"holidays":[],"courses":[],"slots":[],"sessions":[],"assessments":[],"settings":{}}`. IDs are preserved.
- **R22** `restore_json` validates `format`, rejects `schema_version` greater than the app's, then replaces **all** data in one transaction. Before restoring, the app copies the current DB file to `{data_dir}/backups/pre-restore-{YYYYMMDD-HHMM}.sqlite`. On any error, the DB is unchanged.
- **R23** CSV exports, with a header row, sorted by date:
  - `attendance.csv`: `date,start,end,course_code,course_name,kind,status,replaces_date,note`
  - `assessments.csv`: `course_code,kind,title,due_at,completed,notes`

**Storage**
- **R24** The DB lives at `{ProjectDirs data_dir}/planner.sqlite` unless `ACADEMIC_PLANNER_DB` is set. The directory is created if missing. The DB never lives in the install dir or the repo.
- **R25** Opening a DB runs pending migrations. Opening an already-current DB is a no-op. A DB with `user_version` newer than the app is refused with a clear error.

## 5. Core API (implement these signatures; stub with `todo!()` in M1 so UI work can start in parallel)

```rust

impl Planner {
    pub fn open(path: &Path) -> Result<Self>;
    pub fn open_in_memory() -> Result<Self>;

    // terms & holidays
    pub fn active_term(&self) -> Result<Option<Term>>;
    pub fn save_term(&mut self, input: TermInput) -> Result<Term>;          // create or update; sets active
    pub fn set_holidays(&mut self, term_id: i64, days: &[Holiday]) -> Result<()>;

    pub fn list_slots(&self, on: NaiveDate) -> Result<Vec<Slot>>;            // slots valid on a date

    pub fn sessions_for_course(&self, course_id: i64, now: NaiveDateTime) -> Result<Vec<SessionView>>;
    pub fn set_status(&mut self, id: i64, status: Status, now: NaiveDateTime) -> Result<()>;
    pub fn reschedule(&mut self, id: i64, makeup: MakeupInput) -> Result<Session>;

    pub fn set_completed(&mut self, id: i64, done: bool) -> Result<()>;
    pub fn delete_assessment(&mut self, id: i64) -> Result<()>;
    pub fn list_assessments(&self, filter: AssessmentFilter) -> Result<Vec<Assessment>>;

    // settings, backup, export
    pub fn settings(&self) -> Result<Settings>;
    pub fn save_settings(&mut self, s: &Settings) -> Result<()>;
    pub fn export_json(&self, now: NaiveDateTime) -> Result<String>;
    pub fn restore_json(&mut self, json: &str) -> Result<()>;
    pub fn export_attendance_csv<W: Write>(&self, w: W) -> Result<()>;
    pub fn export_assessments_csv<W: Write>(&self, w: W) -> Result<()>;

    // M5
    pub fn due_reminders(&mut self, now: NaiveDateTime) -> Result<Vec<Reminder>>; // logs to reminder_log, never returns one twice

```

`SessionView` includes course code/name, `display_status` ("Pending" / "Attended" / "Absent" / "Cancelled" / "Rescheduled → 2026-01-15"), and `is_past` (`now >= session start`, i.e. attendance may be marked per R12; `now` is passed in because core never reads the clock).

## 6. UI (Slint), minimal

**Visual rules come from `DESIGN.md`.** Every color, font size, spacing, and radius in `.slint` files references `Theme.*` (from `ui/theme.slint`). Hardcoded hex values or pixel sizes outside `theme.slint` are a review failure, enforced with a grep check in CI (§12).

One window. Left nav with 5 pages. Forms are inline panels or dialogs. Every list has an empty state.

1. **Dashboard:** sections for R16–R20. Each awaiting-attendance row has Attended / Absent / Cancelled buttons. A banner lists courses that are below target.
2. **Timetable:** a week view (prev/next/today buttons) showing that week's sessions grouped by weekday. Clicking a session offers: mark status, cancel, reschedule (date + time + room + optional note; the note is stored on the makeup session), and shows any stored note read-only. A second tab, "Rules", lists slots with add/edit (asks for an effective date)/end actions. **A grouped list is acceptable; a visual time grid is out of scope.**
3. **Courses:** a list (with a show-archived toggle) and create/edit/archive. Course detail shows the attendance summary, the full session list with status buttons, and an "Add makeup class" form (date, start, end, room, note) for R10.
4. **Assessments:** a list with filters (upcoming / overdue / completed / all), create/edit/delete, and a complete checkbox.
5. **Settings:** term (name, start, end), holidays (add a single date or an inclusive date range with one label, expanded into one holiday per day; remove per day), reminder minutes, upcoming window, notifications on/off, Backup (save JSON), Restore (open JSON, with a confirm dialog), Export CSV, and the DB file location shown as text.

Date/time inputs: text fields validated as `YYYY-MM-DD` / `HH:MM` with inline errors. Date pickers are out of scope.

## 9. M4 manual smoke checklist (human, ~5 minutes)

Create term → add 2 courses → add 3 slots → the timetable shows this week → mark one past session attended and one absent → course shows 50.0% → cancel a session → reschedule one → add an assessment due tomorrow → dashboard shows it → back up → delete a course's data / restore → data is back → export CSVs and open them in a spreadsheet app.

Never run Spec Kit on the whole app at once. Per-milestone features keep `tasks.md` small, and each step re-reads it.

### 12.2 Caveman: chat only
- Install: `claude plugin marketplace add JuliusBrussee/caveman` then `claude plugin install caveman@caveman`. Use the default intensity.
- **Applies to:** agent chat replies, plans, and status updates.
- **Never applies to:** code, code comments, test names, commit messages, README, `docs/spec.md`, `DESIGN.md`, or Spec Kit artifacts. Telegraphic text in permanent files hurts readability and hides rule details.
- Run `/caveman-compress` on `CLAUDE.md`/`AGENTS.md` **once at M0** and review the diff by hand: every rule must survive. This is the larger saving, because that file is loaded on every turn.
- Check savings with `/caveman-stats` after M2. If it saves under 10%, keep it anyway; there is no quality cost at default intensity.

### 12.3 DESIGN.md
- Lives in the repo root and follows the Google Labs format (alpha). Validate with `npx @google/design.md lint DESIGN.md`. The format is still changing, so if lint rejects a key, fix the file to match the current spec. Do not drop the tokens.
- **M0:** run `frontend-design` with this brief: *quiet, dense student productivity tool; light theme; status colors for Attended / Absent / Cancelled / Pending / Below-target that never carry meaning by color alone (always paired with a text label).* Output goes straight into `DESIGN.md` (tokens + the prescribed `##` sections). The human approves it before M1.
- **Start of M4:** the agent hand-translates the tokens into `ui/theme.slint` (`export global Theme { … }`), and the UI references only `Theme.*`.
- **End of M4:** the human (or computer use) takes one screenshot per page and an empty-state screenshot. Run `impeccable` on them against `DESIGN.md`. Fix only high-severity items, and fix them in `theme.slint`/layout, never by hardcoding values.
- CI check (M4+): `! grep -rnE '#[0-9a-fA-F]{6}|[0-9]+px' crates/app/ui --include=*.slint | grep -v theme.slint`

### 12.4 Other token rules (bigger savings than any plugin)
1. **One milestone per session.** `/clear` between milestones. Hand off state through git and `specs/`, not chat history.
2. **Load only what the milestone needs:** spec sections by number, not the whole file.
3. **Subagents only for read-only exploration** (e.g. "find how Slint VecModel is used in examples"). Never use them for implementation, because each subagent starts cold.
4. **Use a cheaper model for mechanical milestones** (M3 CSV/JSON, M6 packaging) and the strongest one for M2 (logic) and M4 (UI).
5. **Paste a failing test's output, not the whole log.** The gate prints a summary; quote only the failures.

### 12.5 Session handoff (your existing `.claude/state` pattern)
- `progress.json`: `{"milestone": "M2", "phase": "implement", "tasks": {"T001": "done", ...}}`, using Spec Kit task IDs. The agent updates it after each task, not at the end.
- `checkpoint.md`, at most 15 lines: current milestone, last green gate (commit hash), next task, open questions. A new session reads **only** `AGENTS.md` + `checkpoint.md` + the current `specs/<milestone>/tasks.md`. This replaces re-reading chat history and is the cheapest way to resume after `/clear` or an expired prompt cache.
