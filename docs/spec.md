# Academic Planner: MVP Specification (agent-ready, v2)

**Goal:** A local-first, open-source desktop app for university courses, weekly timetables, assessments, and manually logged attendance. Native desktop UI (no WebView), no account, no server.

**How to use this spec with a coding agent:** Build milestones **M0 → M6 in order**, one milestone per agent session. A milestone is done only when its **Done-when** commands pass. Rule IDs (`R*`) and test IDs (`T*`) are referenced from code comments and test names so the agent and the reviewer can trace coverage. **The MVP is usable after M4** (`cargo run -p app`). M5 and M6 are polish and distribution. **M7–M10** (after v0.1.1) extend the app; their decisions, schema, rules, API, UI, and tests are all in §13.

## 1. Fixed decisions (do not re-decide)

| Area | Decision |
|---|---|
| Language | Stable Rust, edition 2021, `Cargo.lock` committed |
| UI | Slint (`.slint` files compiled in `build.rs`) |
| DB | SQLite via `rusqlite` with `bundled`; `PRAGMA foreign_keys=ON`, `journal_mode=WAL` |
| Migrations | Hand-rolled: embedded SQL files, version tracked with `PRAGMA user_version` |
| Dates | `chrono` **naive local** types only (`NaiveDate`, `NaiveTime`, `NaiveDateTime`). No time zones. Stored as TEXT: `YYYY-MM-DD`, `HH:MM`, `YYYY-MM-DDTHH:MM` |
| Clock | Core never reads the system clock. Every time-dependent function takes `today`/`now` as a parameter. Enforced by `clippy.toml` `disallowed-methods` (`chrono::Local::now`, `chrono::Utc::now`, `std::time::SystemTime::now`) in the core crate |
| Errors | `thiserror` in core, `anyhow` in app |
| Serialization | `serde`, `serde_json`, `csv` |
| Paths | `directories::ProjectDirs` data dir; env var `ACADEMIC_PLANNER_DB` overrides the DB path (dev/tests) |
| File dialogs | `rfd` |
| Notifications (M5) | `notify-rust` |
| Saving | Every mutation commits immediately. No save button |
| Weekday | ISO numbering: 1 = Monday … 7 = Sunday |
| Network | Only the updater (M7, §13.1) and the public-holiday fetch (M16, §13.11) use the network: GitHub Releases and Google's public holiday calendar. Both run in the app crate, never in core. Everything else stays local |
| Updates (M7) | `cargo-packager-updater`; updates are minisign-signed and verified against a public key embedded at build time (human decision 2026-10-29) |
| License | Decide in **M0**, not at release, because the Slint license option constrains the repo license. Verify Slint's current license terms and note any attribution requirement in `NOTICE`/README |

## 3. Data model (exact schema, migration 001)

```sql
CREATE TABLE term (
  id          INTEGER PRIMARY KEY,
  name        TEXT NOT NULL,
  start_date  TEXT NOT NULL,
  end_date    TEXT NOT NULL,
  is_active   INTEGER NOT NULL DEFAULT 0,
  CHECK (end_date >= start_date)
);
CREATE UNIQUE INDEX one_active_term ON term(is_active) WHERE is_active = 1;

CREATE TABLE holiday (
  term_id  INTEGER NOT NULL REFERENCES term(id) ON DELETE CASCADE,
  date     TEXT NOT NULL,
  label    TEXT,
  PRIMARY KEY (term_id, date)
);

CREATE TABLE course (
  id                  INTEGER PRIMARY KEY,
  term_id             INTEGER NOT NULL REFERENCES term(id),
  code                TEXT NOT NULL,
  name                TEXT NOT NULL,
  instructor          TEXT,
  room                TEXT,
  notes               TEXT,
  min_attendance_pct  INTEGER CHECK (min_attendance_pct BETWEEN 0 AND 100),
  archived            INTEGER NOT NULL DEFAULT 0,
  UNIQUE (term_id, code)
);

CREATE TABLE slot (                         -- recurring timetable rule
  id          INTEGER PRIMARY KEY,
  course_id   INTEGER NOT NULL REFERENCES course(id),
  weekday     INTEGER NOT NULL CHECK (weekday BETWEEN 1 AND 7),
  start_time  TEXT NOT NULL,
  end_time    TEXT NOT NULL,
  room        TEXT,                         -- NULL = use course.room
  valid_from  TEXT NOT NULL,                -- inclusive
  valid_to    TEXT,                         -- inclusive; NULL = until term end
  CHECK (end_time > start_time)
);

CREATE TABLE session (                      -- one dated class occurrence
  id                   INTEGER PRIMARY KEY,
  course_id            INTEGER NOT NULL REFERENCES course(id),
  slot_id              INTEGER REFERENCES slot(id),          -- NULL for makeup
  kind                 TEXT NOT NULL CHECK (kind IN ('regular','makeup')),
  date                 TEXT NOT NULL,
  start_time           TEXT NOT NULL,
  end_time             TEXT NOT NULL,
  room                 TEXT,
  status               TEXT NOT NULL DEFAULT 'pending'
                       CHECK (status IN ('pending','attended','absent','cancelled')),
  replaces_session_id  INTEGER REFERENCES session(id),       -- set on a makeup that reschedules an original
  note                 TEXT,
  UNIQUE (slot_id, date),
  CHECK (end_time > start_time),
  CHECK ((kind = 'regular') = (slot_id IS NOT NULL))
);

CREATE TABLE assessment (
  id                      INTEGER PRIMARY KEY,
  course_id               INTEGER NOT NULL REFERENCES course(id),
  kind                    TEXT NOT NULL CHECK (kind IN ('quiz','exam','assignment','other')),
  title                   TEXT NOT NULL,
  due_at                  TEXT NOT NULL,
  notes                   TEXT,
  completed               INTEGER NOT NULL DEFAULT 0,
  remind_minutes_before   INTEGER CHECK (remind_minutes_before >= 0)  -- NULL = no reminder
);

CREATE TABLE setting (key TEXT PRIMARY KEY, value TEXT NOT NULL);
-- defaults: class_reminder_minutes=15, upcoming_window_days=7, notifications_enabled=1,
--           check_updates_on_start=1 (M7, §13.1),
--           theme=system (system | light | dark; a missing row reads as system; human decision 2026-10-29)

CREATE TABLE reminder_log (                 -- M5: prevents duplicate notifications
  kind     TEXT NOT NULL CHECK (kind IN ('session','assessment')),
  ref_id   INTEGER NOT NULL,
  fire_at  TEXT NOT NULL,
  PRIMARY KEY (kind, ref_id, fire_at)
);
```

Migration 002 (M9: credits, rule sets, marks, grade scale) is defined in §13.3.

There is **no "rescheduled" status**. A rescheduled occurrence is `status='cancelled'` and is referenced by a makeup session's `replaces_session_id`. The UI derives the label "Rescheduled → {date}".

## 4. Business rules

**Terms and courses**
- **R1** Exactly zero or one active term. Courses, sessions, dashboard, and summaries operate on the active term.
- **R2** Validation errors (returned as `Error::Validation`, never panics): term end < start; slot end ≤ start; `min_attendance_pct` outside 0–100; empty course code/name/assessment title; duplicate course code within a term.
- **R3** Archiving a course hides it from the dashboard, timetable, and default lists. Its sessions and assessments are kept, and it generates no new sessions. Unarchiving resumes generation on the next sync.

**Session generation**: `sync_sessions(today)`, idempotent
- **R4** For each slot of each non-archived course in the active term, the generation range is `[max(term.start, slot.valid_from), min(term.end, slot.valid_to ?? term.end)]`, both ends inclusive. Every date in that range with `weekday == slot.weekday` that is **not a holiday** gets exactly one `regular` session (`UNIQUE(slot_id,date)`), copying start/end/room from the slot at creation time.
- **R5** Sync deletes a session only if **all** of these hold: `kind='regular'`, `status='pending'`, `date >= today`, and it is no longer produced by R4. Past sessions and any non-pending session are never deleted by sync.
- **R6** Sync runs on app start, after any term/holiday/course/slot change, and when the date rolls over (checked by the app's 60-second timer).
- **R7** Editing a slot = `change_slot(slot_id, new_values, effective_from)`: set old slot `valid_to = effective_from - 1 day`, insert a new slot with `valid_from = effective_from`, then sync. Past sessions keep their stored date/time/room (**sessions are snapshots**). UI default for `effective_from` is today.

**Exceptions**
- **R8** Cancel an occurrence: set that session's status to `cancelled`. The slot is unchanged, and sync never recreates or resets it.
- **R9** Reschedule (one transaction): create a `makeup` session with `replaces_session_id = original.id`, and set the original to `cancelled`. Rescheduling a session that is already attended or absent is an error.
- **R10** One-off makeup class: a `makeup` session with `replaces_session_id = NULL`. It counts like any other session.

**Attendance**
- **R11** Statuses: `pending` (default), `attended`, `absent`, `cancelled`. Attendance is never inferred automatically.
- **R12** `attended`/`absent` can be set only when `now >= session start`. `cancelled` and reset-to-`pending` are allowed at any time.
- **R13** `pct = attended / (attended + absent) × 100`, rounded to 1 decimal. If the denominator is 0, return `None`; the UI shows "—".
- **R14** `below_target = target.is_some() && pct.is_some() && pct < target`.
- **R15** The summary per course returns counts of attended, absent, cancelled, and pending (past + future), plus `pct` and `below_target`.

**Dashboard**: `dashboard(now)`
- **R16** Today's classes: all sessions with `date == now.date()` for non-archived courses, sorted by start, with status.
- **R17** Next class: the earliest `pending` session with `start > now` (non-archived).
- **R18** Upcoming assessments: incomplete, `now <= due_at <= now + upcoming_window_days`, sorted by due date.
- **R19** Overdue: incomplete with `due_at < now`.
- **R20** Awaiting attendance: `pending` sessions with `end <= now` (non-archived), oldest first. Sessions in progress are not included.

**Backup and export**
- **R21** `export_json(now)` → `{"format":"academic-planner-backup","schema_version":N,"exported_at":"…","terms":[],"holidays":[],"courses":[],"slots":[],"sessions":[],"assessments":[],"settings":{}}`. IDs are preserved.
- **R22** `restore_json` validates `format`, rejects `schema_version` greater than the app's, then replaces **all** data in one transaction. Before restoring, the app copies the current DB file to `{data_dir}/backups/pre-restore-{YYYYMMDD-HHMM}.sqlite`. On any error, the DB is unchanged.
- **R23** CSV exports, with a header row, sorted by date:
  - `attendance.csv`: `date,start,end,course_code,course_name,kind,status,replaces_date,note`
  - `assessments.csv`: `course_code,kind,title,due_at,completed,notes`

**Storage**
- **R24** The DB lives at `{ProjectDirs data_dir}/planner.sqlite` unless `ACADEMIC_PLANNER_DB` is set. The directory is created if missing. The DB never lives in the install dir or the repo.
- **R25** Opening a DB runs pending migrations. Opening an already-current DB is a no-op. A DB with `user_version` newer than the app is refused with a clear error.

## 6. UI (Slint), minimal

**Visual rules come from `DESIGN.md`.** Every color, font size, spacing, and radius in `.slint` files references `Theme.*` (from `ui/theme.slint`). Hardcoded hex values or pixel sizes outside `theme.slint` are a review failure, enforced with a grep check in CI (§12).

One window. Left nav with 5 pages. Forms are inline panels or dialogs. Every list has an empty state.

1. **Dashboard:** sections for R16–R20. Each awaiting-attendance row has Attended / Absent / Cancelled buttons. A banner lists courses that are below target. A mini month calendar (prev/next month; marks today, days with classes, and days with incomplete assessments due) sits beside a day panel listing the selected day's classes (with status buttons) and assessments due; today is selected by default, so the panel replaces the separate "Today's classes" section (R16) (human decision 2026-10-29). Not a visual time grid or date picker (§10).
2. **Timetable:** a week view (prev/next/today buttons) showing that week's sessions grouped by weekday. Clicking a session offers: mark status, cancel, reschedule (date + time + room + optional note; the note is stored on the makeup session), and shows any stored note read-only. A second tab, "Rules", lists slots with add/edit (asks for an effective date)/end actions. **A grouped list is acceptable; a visual time grid is out of scope.**
3. **Courses:** a list (with a show-archived toggle) and create/edit/archive. Course detail shows the attendance summary, the full session list with status buttons, and an "Add makeup class" form (date, start, end, room, note) for R10.
4. **Assessments:** a list with filters (upcoming / overdue / completed / all), create/edit/delete, and a complete checkbox.
5. **Settings:** term (name, start, end), holidays (add a single date or an inclusive date range with one label, expanded into one holiday per day; remove per day), reminder minutes, upcoming window, notifications on/off, Backup (save JSON), Restore (open JSON, with a confirm dialog), Export CSV, and the DB file location shown as text.

Appearance: a three-way System / Light / Dark switch (monitor, sun, and moon icons) stays fixed in the window's top-right corner on every page; System follows the operating system's appearance; the choice is saved in settings and applies at once (human decision 2026-10-29).

Date/time inputs: text fields validated as `DD-MM-YYYY` / `HH:MM` with inline errors (human decision 2026-10-29). From M8, times are shown and entered in 12-hour form (R31–R32). M7 adds an About page, M9 a Rules page, and M10 an Import panel (§13). Dates shown to the user read like "October 26, 2026" wherever space allows; storage, JSON backup, and CSV exports keep `YYYY-MM-DD` (§1, R21, R23). Date pickers are out of scope.

## 9. M4 manual smoke checklist (human, ~5 minutes)

Create term → add 2 courses → add 3 slots → the timetable shows this week → mark one past session attended and one absent → course shows 50.0% → cancel a session → reschedule one → add an assessment due tomorrow → dashboard shows it → back up → delete a course's data / restore → data is back → export CSVs and open them in a spreadsheet app.

## 10. Out of scope for v1

Cloud sync/accounts, mobile, AI planning, OCR/PDF import, collaboration, analytics, visual time grid, date pickers, multiple simultaneous terms in the UI, notifications while the app is closed (autostart/background service), and macOS signing/notarization (document the Gatekeeper workaround in the README instead). The M10 JSON import is in scope, but the app never calls an AI service itself: the user runs the AI prompt elsewhere and pastes the result.

### 13.1 M7: About page, updater, pre-migration backup

**Migrations**

### 13.3 M9: credits, rule sets, marks, GPA

**Migration 002**

```sql
ALTER TABLE course ADD COLUMN credits REAL CHECK (credits IS NULL OR credits > 0);   -- NULL = not graded
ALTER TABLE course ADD COLUMN rule_set_id INTEGER REFERENCES rule_set(id);          -- NULL = not graded

CREATE TABLE rule_set (id INTEGER PRIMARY KEY, name TEXT NOT NULL UNIQUE);

CREATE TABLE rule_component (
  id           INTEGER PRIMARY KEY,
  rule_set_id  INTEGER NOT NULL REFERENCES rule_set(id) ON DELETE CASCADE,
  position     INTEGER NOT NULL,
  name         TEXT NOT NULL,
  kind         TEXT NOT NULL CHECK (kind IN ('attendance','items')),
  weight_pct   REAL NOT NULL CHECK (weight_pct > 0 AND weight_pct <= 100),
  item_count   INTEGER CHECK (item_count >= 1),          -- items: N items held
  best_count   INTEGER CHECK (best_count >= 1),          -- items: best K counted
  item_max     REAL CHECK (item_max IS NULL OR item_max > 0),  -- items: marks each item is out of; NULL = the component's marks for that course
  is_final     INTEGER NOT NULL DEFAULT 0,
  UNIQUE (rule_set_id, name)
);

CREATE TABLE attendance_band (
  component_id  INTEGER NOT NULL REFERENCES rule_component(id) ON DELETE CASCADE,
  min_pct       REAL NOT NULL CHECK (min_pct BETWEEN 0 AND 100),
  credit_pct    REAL NOT NULL CHECK (credit_pct BETWEEN 0 AND 100),
  PRIMARY KEY (component_id, min_pct)
);

CREATE TABLE grade_scale (
  letter   TEXT PRIMARY KEY,
  min_pct  REAL NOT NULL UNIQUE CHECK (min_pct BETWEEN 0 AND 100),
  points   REAL NOT NULL CHECK (points >= 0)
);

ALTER TABLE assessment ADD COLUMN component_id INTEGER REFERENCES rule_component(id);  -- NULL = not counted in marks
ALTER TABLE assessment ADD COLUMN score REAL CHECK (score IS NULL OR score >= 0);
```

Seeded defaults (all editable on the Rules page; the band and Lab values are placeholders until the user enters their university's rules):
- **Theory:** Attendance 10% (attendance); Quizzes 15% (items, best 3 of 4, each out of 15); Mid 25% (items, 1 of 1, out of NULL); Final 50% (items, 1 of 1, out of NULL, `is_final`).
- **Lab:** Attendance 30% (attendance); Lab work 40% (items, 1 of 1, out of NULL); Lab final 30% (items, 1 of 1, out of NULL, `is_final`).
- **Attendance bands** (both sets): ≥90 → 100, ≥85 → 90, ≥80 → 80, ≥75 → 70, ≥70 → 60, ≥0 → 0.
- **Grade scale** (UGC Bangladesh): A+ 80 4.00, A 75 3.75, A- 70 3.50, B+ 65 3.25, B 60 3.00, B- 55 2.75, C+ 50 2.50, C 45 2.25, D 40 2.00, F 0 0.00.

**Rules**
- **R33** A graded course has `credits` and a `rule_set_id`. Its total marks = 100 × credits; a component's marks = weight_pct / 100 × total. Credits may be fractional (1.5). A course missing either is "not graded" and is left out of R37–R40.
- **R34** Saving a rule set is validated (`Error::Validation`): non-empty unique name; weights sum to 100 (±0.01); at most one `attendance` component; exactly one `is_final` component and it is `items`; for `items`, 1 ≤ best_count ≤ item_count; an attendance component has at least one band and a band with min_pct 0. Components are updated in place by id; removing a component that has linked scored assessments is an error. Deleting a rule set that a course uses is an error.
- **R35** Attendance component: take the course's R13 pct; the earned fraction is the credit_pct of the band with the highest min_pct ≤ pct. If pct is None, the component is not yet assessed.
- **R36** Items component: the scores of the course's assessments linked to it. Earned fraction = (sum of the best K scores) / (K × item_max), with item_max NULL meaning the component's marks. A score must be ≤ item_max (else `Error::Validation`). With fewer than K scores, missing items count as 0 for secured marks; the assessed fraction is (scores entered, capped at K) / K. Example: best 3 of 4 out of 15, scores 12, 11, 13, 14 → 39/45; with a 45-mark share that is 39 marks.
- **R37** `course_marks`: per component earned marks and marks possible; secured = sum of earned marks; assessed marks = sum of (component marks × assessed fraction); projected pct = secured / assessed × 100 (None if nothing assessed); letter = the grade-scale row with the highest min_pct ≤ projected pct, rounded to 1 decimal.
- **R38** Needed in final, for each grade row: need = min_pct / 100 × total − secured marks of all non-final components; needed score = need / final marks × final item_max, rounded **up** to 1 decimal. Result: "Secured" if ≤ 0, "Not reachable" if above item_max, else the score. Non-final components with missing items count those as 0, and the result lists what was assumed (e.g. "assumes 0 for 1 quiz not entered"). If the final already has a score, show the actual grade instead.
- **R39** Grade scale validation: unique letters and min_pct, a row with min_pct 0, points non-increasing as min_pct decreases.
- **R40** `term_gpa`: over non-archived graded courses in the active term with a projected pct, GPA = Σ(points × credits) / Σ credits, rounded to 2 decimals; None if no course qualifies. It is "final" when every component of every included course is fully assessed, otherwise "projected", and it reports how many graded courses were left out for lack of marks.
- **R41** Backup (amends R21/R22): the JSON gains `rule_sets`, `rule_components`, `attendance_bands`, `grade_scale`; course and assessment rows carry the new columns; `schema_version` becomes 2. Restoring a version-1 backup leaves the courses ungraded and sets the four new tables to the seeded defaults. CSV formats (R23) are unchanged.

### 13.4 M10: courses and timetable import

**Format** (`format` and `version` required; times are 24-hour `HH:MM`; `day` accepts `Mon`/`Monday`/`1`, any case):

**Rules**
- **R42** The whole document is parsed and validated before anything is written. Errors are collected (not just the first) and each names its JSON path, e.g. `courses[2].slots[0].end: must be after start`. Checked: format/version, required fields, dates, times, day names, end > start, credits > 0, min_attendance_pct 0–100, `rule_set` names an existing rule set, duplicate course codes within the file. Unknown keys are ignored with a warning. Any error → nothing is written.
- **R43** Course codes match ignoring case and whitespace (`CSE 4711` = `cse4711`). A new code creates the course with the code as written.
- **R44** An existing code updates only the fields present in the file (absent = keep; explicit `null` = clear). An archived match stays archived and the preview warns.
- **R45** Slots of a course in the file: if the file's slot set (day, start, end, room) equals the course's slots valid on the effective date, nothing changes. Otherwise every current slot is ended at effective − 1 day and the file's slots are added from the effective date (R7 semantics, so past sessions stay as they are). `"slots": []` ends all slots; a missing `slots` key leaves them untouched. New courses' slots start at the effective date.
- **R46** Courses not in the file are never changed or deleted.
- **R47** `term`: if there is no active term, it is required and is created. If an active term exists, it is ignored, and the preview warns when it differs.
- **R48** `preview_import` writes nothing and returns the plan: courses to add, courses to update with field-by-field changes, slot changes per course, and warnings. `apply_import` applies exactly that plan in one transaction, then syncs (R6). Importing the same file twice → the second plan is empty.
- **R49** The effective date defaults to today in the UI and can be changed in the preview (e.g. to the term start for a fresh term).
- **R50** The template and an AI prompt ("convert my timetable to this format…", including the period → time rule for merged cells) ship as `docs/import/template.json` and `docs/import/ai-prompt.md` and are shown in the app with Copy buttons.

### 13.7 M12: bi-weekly slots (human decisions 2026-10-30)

**Migration 003**

**Rules**
- **R54** Term weeks run Monday to Sunday; week 1 is the week that contains `term.start_date`. `term_week_parity(term_start, date)` is `Odd` when the number of whole weeks between the Monday of `term_start`'s week and the Monday of `date`'s week is even (weeks 1, 3, 5, …), else `Even`. Dates before the term follow the same alternation.
- **R55** (amends R4) A slot with `week_parity` set produces a session only on dates whose term-week parity equals it. A holiday skips that week's session but never shifts the pattern. Slots with `week_parity` NULL behave as before.
- **R56** Slot form (Timetable → Rules): a "Bi-weekly" checkbox; when ticked, a "Class this week" checkbox (ticked by default) says whether the slot meets in the current week (the week of today). The stored parity is `term_week_parity(term.start, today)` when ticked, else the other one. Editing a bi-weekly slot pre-fills both from the stored parity and today. Saving keeps R7 semantics (effective date). The conversion is a pure function in `viewmodel.rs`.
- **R57** `shift_biweekly(course_id, from)` ("Move to next week"): every bi-weekly slot of the course that is valid on `from` flips its parity from `from` on. A slot that starts before `from` ends at `from − 1` and a copy with the other parity starts at `from` (R7); a slot that starts on or after `from` is flipped in place. Then, in the same transaction, sync runs with today = `from`: pending regular sessions on or after `from` that the old pattern produced are deleted (R5) and the new pattern's sessions are created. Past and non-pending sessions are never touched. A course with no bi-weekly slot valid on `from` is `Error::Validation`.
- **R58** Dashboard: every pending session of a bi-weekly slot dated today or later (day panel, next class) shows a "Move to next week" button that calls `shift_biweekly(course, session.date)`, then refreshes. Sessions and slots of bi-weekly slots show "Every other week" next to their time on the Dashboard, Timetable (week view and Rules list), and course detail. `SessionView` gains `biweekly: bool`.
- **R59** Import (amends R42, R45): a slot may have `"biweekly": "this_week"` or `"next_week"`, meaning the slot meets in the week of the effective date (R49) or in the week after it; absent or `null` = every week; any other value is a validation error with its JSON path. The value becomes a parity through R54 before planning, and R45 compares slots including parity. The template and AI prompt (R50) document the key.
- **R60** Backup (amends R21, R41): slot rows carry `week_parity`; `schema_version` becomes 3. Restoring a version-1 or version-2 backup makes every slot weekly. CSV formats (R23) are unchanged. Opening a version-2 DB applies migration 003 with the R26 pre-migration copy; existing slots stay weekly.

**Review of the report.** The human saw no sign that a save worked on the Rules page and suspected the "Saved rules" list kept old values.
