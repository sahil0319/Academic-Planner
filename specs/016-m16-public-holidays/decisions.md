# M16 decisions

D1-D16 were fixed by the router before planning. D17 onward were taken by the planner with the recommended option (unattended overnight run). One line each; the human may revisit.

- D1 (router) Migration = next free number: `006_public_holiday.sql` (001-005 exist). The builder renumbers after the final rebase if another migration landed; `SCHEMA_VERSION = MIGRATIONS.len()`; migration test counts stay consistent. Table exactly as the spec.
- D2 (router) `public_holiday` is a cache: not in backups or CSV; a restore leaves its rows alone. Backup `schema_version` still tracks `SCHEMA_VERSION` and the new migration must not break older-backup restores. The setting `public_holiday_country` is in backups.
- D3 (router) HTTP: add `reqwest` (`default-features = false`, features `blocking`, `rustls-tls-native-roots`) and `sys-locale` `"0.3"` as direct dependencies of `crates/app`, with the features the tree already builds, so no new crate enters `Cargo.lock`; licenses MIT/Apache-2.0 are already accepted in `about.toml`. Not `ureq`.
- D4 (router) Network code lives in `crates/app` only: new module `crates/app/src/holidays/` (pure `ics.rs`, pure `locale.rs`, `calendars.rs` with `include_str!` of `data/holiday-calendars.json`, `fetch.rs` with the `HolidayFetcher` trait and the `reqwest` implementation, a testable `service.rs`). Tests inject a fake fetcher; tests and build never touch the network.
- D5 (router) Real fetch: a background `std::thread`, 10 s timeout, one GET of the feed URL, result posted back with `slint::invoke_from_event_loop` (as `pages/about.rs`). Triggers: once per launch (active term and country not Off), country change, Retry. Failure keeps cached rows and shows "Couldn't load public holidays" with Retry inline in the Settings card (not a toast); success replaces that country's rows and refreshes the dashboard and the Settings list. Events kept = dated within the years of the active term (start year to end year inclusive).
- D6 (router) Ship `crates/app/data/holiday-calendars.json` (ISO code to Google calendar id) for at least BD, IN, PK, NP, LK, MY, SG, ID, AE, SA, GB, IE, US, CA, AU, NZ, DE, FR. The country choice = those plus "Off". Builder uses best-known ids and may verify each with one manual request during development (never in tests or `build.rs`); verified and unverified ids are recorded here (D40).
- D7 (router) The parser keeps VEVENTs whose unescaped DESCRIPTION contains "Public holiday"; observances are dropped. All-day `DTSTART;VALUE=DATE`, `DTEND` exclusive (one entry per date), date-time `DTSTART` uses its date, folded lines unfolded, SUMMARY unescaped as the name. Pure function in the app crate; sample feeds saved under `crates/app/src/holidays/testdata/`.
- D8 (router) Locale mapping: region part uppercased; no region -> Off; region not in the table -> Off. OS locale via `sys_locale::get_locale()` in a thin untested wrapper. Setting `public_holiday_country`: absent = OS region; `off` (lowercase) = Off; else an ISO code; a stored code not in the table = Off. Never an IP lookup.
- D9 (router) Core API exactly as the spec: `PublicHoliday { date, name }`, `set_public_holidays(&mut self, country, days)` (replace that country's rows in one transaction), `public_holidays_between(&self, country, from, to)` ordered by date then name. Core has no Slint, clock, or network. Country-setting getter/setter only if the existing pattern fits; keep signature changes minimal.
- D10 (router) Dashboard: public holiday day gets `calendar-public-holiday` (token already in `theme.slint`) and a legend entry; fill priority today, then term day off kind (R74), then public holiday, then weekend; the day panel lists "Public holiday: {name}" and, when also a term day off, both lines. Formatting in `viewmodel.rs` with unit tests; `.slint` only binds.
- D11 (router) Settings card "Public holidays": country choice incl. Off, status line, Retry shown only on failure, cached public holidays inside the active term with a checkbox each, "Add selected as holidays". Each ticked date that is not already a day off becomes a `holiday` labelled with the public name (R71), via the existing core path, then sync (R6). Toast through `App::toast`: "Added N holidays." / "Added 1 holiday." / "Added N holidays. M skipped, already a day off."; none ticked -> inline "Tick at least one public holiday."; errors inline (R89/R89a).
- D12 (router) UI rules: `Theme.*` only; no raw hex or px outside `ui/theme.slint` (the theme grep scans comments too); square corners; no logic in `.slint` beyond bindings; formatting in `viewmodel.rs` with unit tests; reuse the Settings `SectionCard` components.
- D13 (router) T77 and T78 are core integration tests in `crates/core/tests/m16_public_holidays.rs`; the app-side helper that decides added vs skipped is unit-tested in the app crate and the sessions-deleted-by-sync part is in the core test; T75, T76, T79 are app crate unit tests (T79 uses the fake fetcher through the service layer and checks status text and retry flag from `viewmodel.rs`).
- D14 (router) Task order: tests first (tester); core migration, model, settings, backup check; app holidays module; service and controller wiring; view model; Settings card; dashboard; gate. One commit per coherent step, prefix `M16:`. `[P]` only when files do not overlap.
- D15 (router) The real network fetch cannot be verified overnight; `quickstart.md` lists the manual checks for the human.
- D16 (router) No version bumps, no push or tag, no real user database.
- D17 The country setting is not a field of `Settings` (it is `Copy` and built in many places, so a `String` field would break every literal). Core gets two methods, `public_holiday_country() -> Result<Option<String>>` and `set_public_holiday_country(&str)`, storing the raw text under `pub(crate) const SETTING_PUBLIC_HOLIDAY_COUNTRY` in `db.rs`; the mapping to Off or a code lives in the app.
- D18 `set_public_holidays` stores the country text as given (the app always passes the upper-case ISO code), uses `INSERT OR IGNORE` so a repeated `(date, name)` never fails, and an empty slice clears the country. `public_holidays_between` is inclusive on both ends.
- D19 Backup needs no code change: export writes every `setting` row, restore re-inserts them, and the restore `DELETE` list has no `public_holiday`. No new version constant. Checked: `migrations.rs`, `m9_migration.rs`, `m12_biweekly.rs`, `m15_exam_periods.rs`, `m19_default_bands.rs`, `m3_backup_*.rs`, `m9_backup.rs` use `SCHEMA_VERSION` symbolically; no literal count to change. `DAY_OFF_KIND_VERSION` (5) and `DEFAULT_BANDS_MIGRATION` stay as they are. The backup gets a doc comment citing R80 only.
- D20 Dependencies verified offline with `cargo tree` and the registry: `reqwest` 0.12.28 (MIT OR Apache-2.0, already built with `blocking` and `rustls-tls-native-roots` through `cargo-packager-updater`), `sys-locale` 0.3.2 (MIT OR Apache-2.0, already pulled by `i-slint-core`), `serde_json` (workspace dependency, already used by core). Adding them to `crates/app/Cargo.toml` changes only the `app` package's dependency list in `Cargo.lock`; the builder checks `git diff Cargo.lock` shows no new `[[package]]`. `ureq` (2.12.1, 3.5.0) is also in the tree but reqwest already carries the TLS roots setup.
- D21 `holiday-calendars.json` is an array of `{ "code", "name", "id" }`; parsed with `serde_json::Value`; the Settings choice lists "Off" first, then names sorted alphabetically.
- D22 The description filter is a case-sensitive substring check for "Public holiday" on the unescaped DESCRIPTION (Google writes exactly "Public holiday" or "Observance"); an event without that text is dropped.
- D23 Parser details: lines split on CRLF or LF; a line starting with a space or tab continues the previous one (the first character is dropped); property name = text before the first `:` or `;`; escapes `\n`, `\N`, `\,`, `\;`, `\\` unescaped; `DTSTART` value date or date-time: the first 8 digits are the date; all-day events expand to one entry per date until `DTEND` (exclusive); a missing or earlier `DTEND` means one day; date-time events give one entry (their `DTSTART` date); `RRULE` is ignored (Google expands events); an event without `SUMMARY` or `DTSTART` is skipped; output deduplicated and sorted by date then name.
- D24 Older-backup test uses the literal `schema_version` 5 (the last version before M16), not `SCHEMA_VERSION - 1`, so it survives a renumbering (same idea as M15 D24).
- D25 Module layout: `crates/app/src/holidays/{mod,ics,locale,calendars,fetch,service,tests}.rs` plus `testdata/*.ics`; page glue in `crates/app/src/pages/public_holidays.rs`; view-model additions in `viewmodel.rs` with tests in `viewmodel/tests.rs`.
- D26 `service::fetch_events` is the worker-thread half: it fails when the code is not in the table, the fetch fails, or the body has no `BEGIN:VCALENDAR` (so an error page answered with 200 never wipes the cache); `service::apply_fetch` is the UI-thread half and writes only on success. A successful fetch with zero events in the term years replaces the country's rows with none.
- D27 `Country { Off, Code(String) }` with `country_from_locale`, `resolve_country(setting, os_locale)`, and `setting_value`; the setting is never written until the human picks a country (an absent setting keeps following the OS region).
- D28 Page-glue state is a UI-thread `thread_local` (status, in-flight flag, ticked row keys, weak `App` handle) because the `invoke_from_event_loop` closure must be `Send`. A result for a country that is no longer the current one is dropped; a second request while one is in flight is ignored; a finished fetch calls `refresh_all` (no sync, no toast).
- D29 Status texts: Idle "", Loading "Loading public holidays…", Updated "Updated today" (same day) or "Updated {date}" (later day, `format_date`), Failed "Couldn't load public holidays" (only Failed shows Retry). Country Off or no active term: status "" and no request. The empty list text is "No public holidays in this term." (with a term) or "Create a term to see its public holidays." (without).
- D30 `CalendarDay` gains `public_holiday: String` set by the new pure `mark_public_holidays` (so `month_grid` and its tests keep their signature); `cell_fill_key` gives the Slint `day-off` key: day off kind key, else `public-holiday`, else empty. The cell label gains ", public holiday {names}" so the fill is never the only cue.
- D31 `calendar_legend()` = `day_off_legend()` (unchanged, three entries, M15 test stays) + "Public holiday"; the dashboard binds the four entries; layout: Holiday, Mid exam, Final exam on line 1, Public holiday with Weekend and Assessment due on the following line(s); the legend always lists the Public holiday entry.
- D32 Day panel: the existing day off line first, then "Public holiday: {name}" (several names on one date joined with "; "), in a new `DashboardState.panel-public-holiday` line.
- D33 The dashboard reads cached rows of the resolved country for the visible grid range; the Settings list reads the active term's `start..=end` (R79). Cached rows are only ever stored within the active term's years (D5).
- D34 Add selected: the tick set is Rust state keyed by `"{YYYY-MM-DD}|{name}"`; `plan_add_public_holidays` walks ticked rows in date, name order, adds a `Holiday` (label = public name) for a date that is not yet a day off of any kind, and counts the rest as skipped (also a second ticked row on a date added a moment before). `added == 0` writes nothing, runs no sync, and still shows the toast (text "Added 0 holidays. M skipped, already a day off."). Ticks clear after a click and after a country change.
- D35 Retry runs the same request as the launch fetch for the current country; it is ignored without an active term, with Off, or while a fetch runs.
- D36 Startup: `pages::public_holidays::wire` next to the other `wire` calls and `start` right after the first `app.changed(true)` in `main.rs`; `settings::refresh` calls `public_holidays::refresh`; `changed_then_toast` in `settings.rs` becomes `pub(super)` so the glue reuses the "no toast when the page message holds an error" rule.
- D37 Settings card widgets: `ComboField` (country), `CheckBox` (rows, as `courses.slint`), `LinkButton` "Retry", `SecondaryButton` "Add selected as holidays"; new Slint struct `PublicHolidayRow { key, date, name, checked }`; the card sits after the Final exams card.
- D38 Locale parsing: drop any `.encoding` or `@modifier` suffix, split on `-` or `_`, skip the language subtag, ignore a 4-letter script subtag, take the first 2-letter alphabetic subtag as the region (uppercased); a tag without one -> Off. Stored setting codes are compared exactly (upper-case); `bd` is not a code (-> Off).
- D39 Public holidays never skip classes and never trigger a sync by themselves (R79); only Add selected does, through the existing `set_holidays` and `changed_then_toast(.., true, ..)` path.
- D40 Calendar ids (all UNVERIFIED guesses from the Google pattern `en.<region>#holiday@group.v.calendar.google.com`; the planner had no network, and the builder records here which ones a single manual request confirmed): BD `en.bd`, IN `en.indian`, PK `en.pk`, NP `en.np`, LK `en.lk`, MY `en.malaysia`, SG `en.singapore`, ID `en.indonesian`, AE `en.ae`, SA `en.saudiarabian`, GB `en.uk`, IE `en.irish`, US `en.usa`, CA `en.canadian`, AU `en.australian`, NZ `en.new_zealand`, DE `en.german`, FR `en.french`. BD is given by the spec; US, GB, IN, CA, AU, DE, FR, IE follow Google's well-known regional names; the rest (PK, NP, LK, AE, SA, ID, MY, SG, NZ) are the least certain. A wrong id only makes that country show "Couldn't load public holidays".
- D41 `quickstart.md` is short and lists manual checks only (D15); it is not a test script.
- D42 Test placement: core `m16_public_holidays.rs` (T77, T78); app `holidays/tests.rs` (T75, T76, T79 and service tests); app `viewmodel/tests.rs` (add plan, texts, legend, fills). The tester writes the `.ics` sample feeds; the builder creates the module files, so test commits may not compile until T005-T009 land (as in earlier milestones).
